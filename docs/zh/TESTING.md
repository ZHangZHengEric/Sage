# 测试方法

测试应能发现真实回归，同时便于理解、修改和执行。不设测试数量目标。本规范适用于 SDK 和应用测试；修改时仍以用户指定的组件、版本为范围。

## 先明确要获得的证据

添加测试前，先说明可能退化的行为、能够区分对错的可观察结果，以及哪些现有测试已经覆盖它。配置调整应先判断纯规则或校验测试是否足够。修复缺陷时，保留能检出原始问题的场景。

不要因为存在一个函数就添加一个测试。低影响、可逆的修改不需要新增复述实现的测试。公开协议、存储契约和仍受支持的迁移行为，即使测试很简单，也应保留。

## 选择能证明问题的最小边界

| 边界 | 能证明什么 | 常用构造 |
| --- | --- | --- |
| 纯规则或校验 | 归一化、分类、限制、schema | 直接调用函数或模型 |
| Provider 或适配器契约 | 实际载荷、错误映射、生命周期及清理 | 真实适配器配合假的外部客户端 |
| Runtime 集成 | 已接受的配置进入执行和持久状态 | 脚本模型、真实 runtime、临时存储 |
| 进程或数据库验收 | 重启持久性、操作系统隔离、数据库事务 | 真实子进程、原生沙箱、测试数据库 |
| 真实 Provider 验收 | 实际上游行为 | 显式配置凭证并接受调用费用 |

假的 SQL 游标不能证明数据库兼容性，内存存储不能证明进程死亡后的持久性，SDK 测试不能证明宿主 UI 可用。报告中应明确这些证据边界。

## 按行为选择用例

独立且可区分的场景可以参数化，并使用有意义的 ID。维度相互影响时，应保留完整组合，例如审批加重启、解析状态加流错误、租户加所有权、提交失败加数据库后端。

维度独立时，在规则层完整覆盖别名和默认值，在真实消费方保留有代表性的集成场景。缺失、边界、非法输入和显式覆盖若走不同决策，应分别覆盖。说明被省去的组合为什么没有新增行为。

翻译键等目录检查可按语言归组，但失败信息应列出全部错误键。独立协议映射和故障模式仍需能够单独定位。把参数移进循环会降低收集节点数，却不一定降低运行或维护成本。

## 共用构造而不隐藏契约

优先复用现有 fixture 和公开 builder。事件样本、模型能力、后端工厂确实重复时，可提取为小型 fixture 模块；测试中的行为预期应继续可见。不要搭通用测试框架，也不要添加没有实际共用构造的单行包装。

整合前先确认集合边界。例如设置页目录可能不包含管理专用工具；覆盖全部装饰器工具的 schema 审查必须保留这些工具，不能仅因公开目录更易查询就缩小范围。新增后端应运行共用契约，并保留自身的锁、事务和故障测试。

示例：[SQL 共用契约](https://github.com/ZHangZHengEric/Sage/blob/main/tests/sagents/v2/test_sql_session_store_contract.py)、[事件样本](https://github.com/ZHangZHengEric/Sage/blob/main/tests/sagents/v2/event_fixture.py)、[装饰器工具发现](https://github.com/ZHangZHengEric/Sage/blob/main/tests/sagents/v2/tool_fixture.py)。

## 在边界上断言行为

检查实际帧名、损失代码和保真度、实际发送的 SQL 与绑定参数、规范事件、持久结果、分发次数和副作用。如果正常映射退化成“不支持”仍能通过，“存在帧或损失报告”就不够。被拒绝的操作应验证没有执行或持久化。

避免按源码子串、历史文件不存在、任意类名，以及不属于契约的整段文案断言。真实依赖约束可用 AST 检查。在协议边界，把传输后的 Prompt 与交给适配器的请求比较；语言选择和作者内容保留由上下文测试负责。

Mock 应放在外部边界，不应重写被测算法。断言容易意外通过时，可临时注入错误映射、丢失字段、额外分发或写入失败，确认测试确实能检出。

## 等待可观察的进展

优先使用 `asyncio.Event`、屏障、已完成的 Future，或有界轮询真实状态，替代任意时长的睡眠。取消执行前先等待 runner 真正进入。并发的否定断言应证明竞争操作已到达争用边界，不能仅证明任务已经创建。

截止时间、退避中断、CPU/磁盘限制，以及操作持续阻塞的断言，应保留真实时间。不要用 `sleep(0)` 或空时钟替换这些保障。只检查恢复问卷内容的测试可以把重试延迟设为零，但必须保留重试次数，并由独立测试覆盖退避和取消。

## 准确验证和报告

每个完整批次先跑相关测试，再运行受影响套件。保留工作区其他修改。测试失败不能成为新增 skip、放宽预期或删除场景的理由。区分实现故障、缺失依赖、操作系统能力不足、执行沙箱限制，以及子进程 `python` 解析到另一套解释器的问题。

在已配置的 Python 3.12+ 环境中，从仓库根目录执行：

```bash
python -m pytest tests/sagents/v2 --collect-only -q
python -m pytest tests/sagents/v2/test_prompt_language_matrix.py -q
python scripts/shared/checks/check_architecture.py
python -m pytest tests/sagents/v2 -m 'not live' -q --durations=10
python docs/scripts/check_docs.py
```

[CI 工作流](https://github.com/ZHangZHengEric/Sage/blob/main/.github/workflows/ci-tests.yml)定义分版本环境和原生沙箱依赖。SQL 契约需要 `SAGE_V2_TEST_MYSQL_DSN` 或 `SAGE_V2_TEST_POSTGRES_DSN`，并应使用专用测试数据库。真实 Provider 测试保持显式启用。被跳过或未选中的路径不能报告为通过。

报告应说明行为覆盖或构造的变化、专项与全量结果、相关耗时及证据限制。区分测试函数、参数化收集节点、实际执行用例、跳过项和真实模型用例。静态盘点或专项审查不能当作完整语义审查或生产证明。

## Agent 执行流程

1. 阅读作用域内的说明，找到现有行为测试。
2. 写清回归问题，以及能检出它的最小边界。
3. 优先复用或扩展已有覆盖，说明新增矩阵或完整 Agent 执行的必要性。
4. 每次完成一个批次，核对失败断言是否有效，并运行专项验证。
5. 明确审查移除的覆盖，保留独立的安全与故障边界。
6. 运行受影响套件和文档检查，报告准确结果及未验证路径。

后续 Agent 的作用域入口是 [tests/AGENTS.md](https://github.com/ZHangZHengEric/Sage/blob/main/tests/AGENTS.md)。该流程不授权无关生产修改、部署、真实 Provider 费用，也不允许为了审计额外扩展业务存储。
