# Streaming UI：让回答直接成为可交互的界面

Sage Desktop 2.1 支持 Agent 边生成、边呈现原生界面：可调参数的计算器、带图表的方案对比、即时统计进度的清单，或者可以翻页的演示文稿。用户直接描述想得到的结果，不需要提协议名称，也不需要让 Agent 先开发一个应用。

这项接入使用 [OpenUI](https://github.com/thesysdev/openui) 官方解析器和 Sage 自己的 Flutter Glass 渲染器。OpenUI 使用 MIT 许可证。Sage 当前注册了 31 类组件，支持的是明确的组件子集，并未嵌入上游 Web 渲染器，也没有实现 OpenUI Cloud Reports API。

## 开启后，直接自然提问

在输入框的 **+** 菜单中开启 **优先交互 UI**。希望后续新聊天默认开启，可在 **设置 → 通用 → 默认开启交互式 UI** 中设置。初始默认关闭，已有聊天保留各自偏好。开启时，宿主把内置 Skill 和组件协议加载进 Agent 上下文，渲染本身不需要调用工具。

可以直接体验：

- “做一个咖啡店经营测算：每天销量 100 杯，每杯售价 25 元，单杯成本 8 元，每月固定成本 20,000 元，按 30 天。参数可调整，收入、成本、利润和利润率立即联动，不需要提交。”
- “比较三个会员方案：免费版支持 1 人，专业版每月 99 元支持 5 人，团队版每月 299 元支持 20 人。用表格和图表比较月费与人均成本。”
- “做一个四周打卡清单，每周三项任务，按周切换，勾选后即时更新总完成次数。”
- “做一份四页咖啡店创业路演：封面、市场机会、经营假设、开店计划。包含图表，每页文字简洁。”

这个偏好用于引导回答形式，不会把所有普通问题强制变成表单。任务确实需要查资料或操作文件时，Agent 仍可使用工具。

## 流式输出如何变成界面

Agent 在助手消息里输出带有 `openui` 语言标记的代码块，其中包含声明式根节点和对注册组件的引用。文本片段到达时，宿主把不断增长的源码交给官方解析器，再将中间树映射为 Flutter 原生组件。前向引用让界面结构可以先出现，内容随后补齐。

这是生成过程中的增量渲染，不是等回答结束后调用一次“打开界面”工具。实际逐 token 的粒度取决于模型服务的分块方式和宿主帧调度：服务端一次发来多个 token，界面就按这个片段更新，不承诺每个 token 都独立重绘一帧。

字体、间距、输入边界、Glass 材质和深浅色由 Sage 控制；Agent 在协议内选择组件结构、分组和内容，不提供任意 CSS 或可执行 JavaScript。当前签名和实现边界见 [接入说明](https://github.com/ZHangZHengEric/Sage/blob/main/app/v2/desktop/README.md#openui)。

## 本地交互与交给助手继续处理

计算器应该在本地重新计算。`Computed` 将支持的运算绑定到输入值，依赖的指标、图表和进度条共用这些绑定。上面的咖啡店参数保持其他条件不变，把日销量从 100 改为 200，正确绑定的月利润会从 31,000 元变为 82,000 元，无需新的模型回答。

勾选任务、切换标签、展开章节和查看图表也属于本地交互。提交按钮承担另一种职责：把所选值作为下一轮消息交回助手，明确请求后续处理；它不能代替本地算术。协议无法表达的公式应说明限制，不能把固定数字展示得像会自动联动一样。

## 校验、修订与侧栏查看

生成过程中，中间预览可能尚未完整。最终输出接入统一的 output self-check 流程，通过官方解析器、组件和依赖规则校验，并在默认值及选定输入边界执行本地计算检查。self-check 不调用任何模型。独立检查项并行执行并汇总错误；每个代码块先解析再执行数值探测，共享解析器的 IPC 仍串行以避免响应错配。只检查最后一条 assistant 消息正文中的 `openui` 代码块；普通文本跳过，不回扫历史消息、思考内容或工具结果。历史仅用于统计修复次数。发现错误时，把具体错误反馈给原生成流程修复，同一用户回合最多三版，并受总预算约束。检查不穷举所有输入组合，也不能推断业务公式是否符合用户原意；通过检查不等于视觉和业务语义绝对正确。模型仍可能输出未通过校验的内容；只读预览不等于交互界面已经交付成功。

同一轮后续 UI 替换旧稿时，正文保留最新稿，旧版本收进 Process Panel，形成可在侧栏查看的一行过程记录。点击 **在侧栏打开** 可以用更大的区域查看当前界面，侧栏与正文共享本地输入状态。

## 演示文稿与可编辑导出

演示文稿使用包含多张幻灯片的 `Deck` 根节点，生成期间即可看到原生 16:9 预览。侧栏通过缩略图在当前幻灯片旁提供导航，也支持全屏演示。校验通过后，宿主从同一份文档导出可编辑 PPTX，不需要 Agent 调用写文件工具制作。

幻灯片支持文字、指标、表格和静态数据图表，并有明确的内容上限。当前不支持 PPTX 导入、自由拖拽编辑、动画和任意 Web 组件。原生预览与 PPTX 共用布局规格，但 PowerPoint 与 Keynote 的字体和具体渲染仍可能不同。

## 使用范围与体验检查

这项能力属于 Desktop 2.1，不代表每个 Sage 宿主都能渲染 OpenUI。桌面安装包内置 Node.js 和解析器；源码运行除桌面环境外还需要 Node.js 22+，安装方式见 [Desktop 指南](DESKTOP.md)。

体验时要同时检查外观和行为：调整输入、切换标签、悬停图表、查看旧稿，以及打开导出的文稿。生成、校验、本地交互和导出是不同的检查环节。模型能力有帮助，但仅凭预览看起来正常，不能判断所有环节都正确。

安装包内容与兼容限制见 [2.1.0 发布说明](https://github.com/ZHangZHengEric/Sage/blob/main/release_notes/v2.1.0.md)。
