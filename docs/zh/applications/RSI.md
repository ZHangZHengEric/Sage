# Agent Package 优化（RSI）

RSI 按设定轮数对输入的 Agent package 进行评测和调优，使用已有模型及宿主绑定的能力，不训练模型权重，也不会自动替换原 Agent。可以使用独立 Python API，或从 Desktop 的 Agent 配置启动后台任务。

## 运行流程

1. 提供 package、授权目标、优化范围和测试集。未提供测试集时，可由测试设计 Agent 生成。支持单轮任务与设有轮数上限的多轮对话。
2. 独立生成并固定验证题，默认 24 道，可配置数量；训练题独立生成。只有没有共同题退化，或训练题已全部通过时，下一轮才按配置补充题目；否则保留当前题集，先修复退化。框架以固定规则校验题目协议、必填字段、ID、split 及执行绑定，不默认调用数据集预审 Agent。生成题校验不通过时，错误交回出题 Agent 限次修复，失败草稿不进入正式题集，原始响应保留。
3. 目标 Agent 使用新 Session 执行基线测试。每个案例由独立的评测 Session 根据评分标准和实际执行证据判断。
4. 调优 Agent 根据训练反馈提出范围内的修改；dev 成绩仅由宿主使用。候选执行前由框架进行固定规则校验，不默认调用候选语义审查 Agent。基线快照保持不变；候选版本直接整体改写包内系统提示词文件，可重组、去重、纠正冲突，不再强制追加 `Optimization guidance:`。固定规则检查授权范围、文件及配置结构、能力绑定、Skill 元数据和资源上限；不通过时将具体错误交回调优 Agent，在同轮最多修正 `max_edit_repairs` 次，仍失败则记录并拒绝该轮候选。业务规则、职责和权限的保留要求作为调优编写原则与评测标准，不把固定校验通过当作语义正确的证明。
5. 每个新候选执行全部累计训练题和固定验证题。新增题不回测历史版本；选版比较固定验证题上的平均分（启用内置资源评分时为验证题的选择分数），不再混入训练均分。新增训练题保存执行与诊断，不因题集变化制造选版增益。验证均分达到 `min_improvement` 即可采纳，允许局部退步；训练成绩继续用于诊断和指导修改，不影响采纳分数。退步训练题持续反馈给调优 Agent，从更好的版本继续修复；验证成绩、逐题退化与选版分数仅保留给宿主及人工审计。
6. 达标后完整复测确认稳定；也可因停滞、轮数或时限退出。即使尚未稳定达标，也保留验证分数更好的候选和完整历史，但不标记推荐，不自动应用。人看的 test 观察独立于这些判断，不作为收敛门槛。

桌面默认另设 12 道只给人看的 test；可设置 0–100 道。test 在基线及每轮保留版本上测量，展示三条分数曲线和逐题点阵。它使用独立会话、单独存储，既不进入任何调优请求，也不参与接受、选版和退出；测试故障显示为测量错误。

每次内部 Agent 调用使用新 Session。调优反馈只包含训练材料、采纳状态与当前父版本，不包含 dev 汇总、通过数、匿名逐题成绩、历史成绩或混合选版分数；dev 题目、原始编号、答案与诊断也保持隐藏。外部 RSI MCP 是用户委托的审查接口，与内部调优输入分开：普通、详细、历史与版本读取可查看 train/dev 的成绩、逐题诊断、执行记录、退化及混合选版指标，`rsi_questions` 可读取 train/dev 题目。紧凑成绩摘要分别返回 `baseline_training`、`selected_training`、`baseline_validation`、`selected_validation`；详细读取保留逐题依据。test、参考答案字段、凭据和无法按 split 分类的原始内部调用仍不经 MCP 返回。外部审查结果不会自动回填内部调优请求；如果外部 Agent 据 dev 反馈继续指导优化，这批 dev 就参与了开发，不能当作独立最终评估。宿主继续使用 dev 选版、决定训练扩增和收敛；采纳状态及调度结果仍是间接反馈，不能据此推断隐藏题的表现。反复用于选择的验证分数不能证明未见任务质量；标准基准可在 RSI 外冻结候选后独立测量，参见 [τ-bench 实验说明](TAU_BENCH.md)。显式 `validation_case_count=None` 仅为旧 SDK 客户端保留历史固定题和可选终测路径。反馈边界变化会改变恢复引擎指纹，旧实验需用原引擎恢复，或另建新实验；不会将旧的含 dev 分数调优请求重放到新协议。

自定义评分器的 `details` 会随固定评分保存，用于独立诊断。文件模式将评分分项、断言理由等放在单独的 `scorer.json`，由 `context.json` 引用；评估环节必须按评分器声明的依据区分失败原因与仅供参考的检查，不能自行增加评分条件。评分明细不会传给执行目标或模拟用户，dev 与 test 的可见性边界保持不变。Python 评分器 v1 子进程协议继续把明细放在已有的 `details` 字段，避免在评分协议的 `grade` 结构中增加宿主内部字段。

受限文件评估若因明确的 `loop.repeated_pattern` 用户输入暂停而未完成，可信宿主可用 `restart_file_evaluator=True` 允许最多两次分析修复。修复请求说明循环原因，重新读取证据并写一次评估文件，不重跑已完成的目标或评分。独立 test 使用相同的本地评估授权；审批、权限暂停和未知副作用不属于这个修复范围。文件读取按约 8 KiB 分页，仍校验每个文件的完整覆盖。

## 断点恢复

进度区的“Token 用量”显示整个实验已回传的累计消耗，按执行、评测、出题、调优、审查及用户模拟分组，展开可查看输入、缓存命中、输出、合计和缓存率。输入包含缓存命中，合计仅为输入加输出；缓存率使用累计缓存命中除以累计输入，不取各次比率的平均。评分器的模型调用和内部诊断都计入评测；独立 test 的调用同样计入总消耗，不向调优角色提供题目内容。每次有用量回传的实际调用（包括重试）都计入消耗，恢复复用已有响应不重复累计。旧实验从可用日志回补并标注记录不完整；未回传用量不猜测为零。新 Desktop 实验不调用候选或数据集审查 Agent，固定规则校验不消耗模型 Token；旧实验已有的审查消耗仍保留。

启动参数随实验记录持久化，实验失败或中断不会清除配置。重新进入进化页面时，会回填上次实验的目标、题量、轮数、限制、优化范围、模型、评分器和导入数据集版本；后台轮询不会覆盖正在编辑的新配置。修改后“开始进化”创建新实验，原实验的冻结配置保持不变。

实验历史支持右键“删除”，确认后从历史列表移除。排队或运行中的实验须先停止；后端同时检查状态和活跃任务。删除采用带操作者和时间的标记，原始配置、运行日志、Agent 版本及数据集保留，不改变旧实验成绩或题数。已删除的历史条目不能再恢复执行。

桌面本地运行提供“恢复进化”；后端接口为 `POST /api/v2/agents/{agent_id}/rsi/runs/{run_id}/resume`，stdio MCP 同时提供 `rsi_resume`。恢复保留同一运行 ID 与版本历史。外部基准镜像由原宿主恢复，不能由缺少业务工具绑定的桌面服务代跑。

SDK 可用 `resume_from=旧日志路径` 与新的 `journal_path` 恢复。首次和恢复调用都应提供相同的 `recovery_binding_id`，由可信宿主对模型路由、采样、权限及测试绑定生成稳定标识。原始 package、目标、题目配置、优化范围和停止规则必须相同。

恢复保留优化版本标识及已完成 case 的原始成绩，不重新执行或重新打分；已完成的内部模型响应也会复用。目标已完成但 eval 中断的单轮案例只继续 eval。多轮对话也在结束后保存 `dialogue_execution_completed`，通过已落盘的 target call 引用恢复完整执行；`dialogue_execution_scored` 单独保存已有评分。随后诊断中断时只重做诊断，评分中断时只补未完成的评分，不重新运行已完整结束的目标对话。被拒绝的评估 JSON 记录 `evaluation_response_rejected`，不会作为有效决策复用。长对话未完成或工具结果未知时，默认抛出 `OptimizationRecoveryRequired`；只有能够证明环境可丢弃、不会重复真实外部副作用的可信宿主，才可传入 `restart_incomplete=True`。该参数不能由调优 Agent 自行授权。 获得可丢弃环境授权后，未完成多轮对话从新会话开始，其旧模拟用户决策与中间评估不再复用；目标的新回复可能不同，必须根据新执行继续对话。已完成案例、完整执行与最终评分仍按原检查点复用。

中断的内部 Agent 若有工具权限，默认同样要求先核对未知副作用。可信宿主若通过冻结的绑定强制某个角色只有受限只读操作，可显式声明 `restart_readonly_roles=("tuning",)`，并提供 `recovery_binding_id`，允许重新执行未完成的只读调优调用；这不是给 Agent 增加工具，也不能把未知写操作自行标为只读。新版 Desktop 的 tuner 是文件编辑器，使用 `file_read`、`file_write`、`file_update`，不能再声明为只读。宿主通过 `restart_package_editor=True` 与冻结绑定声明本轮目录隔离、评估文件只读、无进程权限；未完成的本地编辑先从保留版本重建，已完成编辑从日志中的实际 package 快照恢复。原目标 Agent 不因此增加工具。

文件评估方通过 `restart_file_evaluator=True` 声明每次调用独立目录、输入只读且无进程权限；中断时仅重做未完成的本地评估文件，不重跑已完成的目标执行。

原生运行中可重试的模型传输错误（包括 `model.provider_transient` 和 `model.stream_incomplete`）不作为 0 分训练样本。成功连接后发生的 `invalid_provider_response` 断流，以及首段内容返回前带有精确消息 `response stream could not be completed` 的同类结构化错误，按传输错误处理；显式 HTTP 400/401/403、未知错误消息与鉴权错误不因此自动重试。桌面会保存当前日志、退避等待并恢复，最多连续恢复 12 次；等待时间从 2 秒增长至 60 秒。永久配置错误保留失败记录供处理。等待期间仍能查看原有记录，手动中断后也保留恢复入口。

## 独立评测诊断与同题对照

内部评估、调优及显式启用的审查会读取宿主提供的执行语义。默认确定性运行中，不带工具调用的纯文本回复通常会结束当前运行；工具调用步骤与模型回复步骤不等于两个用户回合。改写流程必须保持原策略规定的先后顺序，不能把待执行的必需动作安排在最终回复之后，也不能假定用户会额外发送“继续”。缺少信息或授权时仍应请求用户补充。

已写出的评估文件与原生运行状态分别校验。在宿主明确授权的本地文件评估中，已知的重复回复暂停可以保留有效文件，但必须有完整的实际读取凭证，并通过结构与引用检查；原生暂停状态仍会保存。缺少读取证据或文件不合格时继续修正。

独立测试使用外部评分器时，评分完成后若诊断失败，仍保存固定评分与执行记录，并明确标记诊断错误。只有所有题目、所有计划执行次数都有有效评分时才形成完整均分；缺失评分不会补零，诊断失败也不会被标记为完成。该机制不重跑已评分的执行，不重新抽样分数，测试材料仍不进入调优输入。 Desktop 恢复被取消或中断的测试检查点时，按原轮次、版本、题目和执行次数复用已完成记录（包括 0 分），仅补缺失执行。优化已完成后，可在桌面点击“继续测试”，或调用 `POST /api/v2/agents/{agent_id}/rsi/runs/{run_id}/resume-tests` 补齐原先声明的独立测试；该入口校验所有者、原配置与模型绑定，不启动调优、不改动版本选择或优化报告。不能通过它事后增加测试集。

没有外部评分器时，eval Agent 自己评分，并根据执行证据给出结构化诊断。有外部评分器时，可信宿主可向 `optimize()` 提供同步或异步 `authoritative_grader(case, observation)`，返回 `OptimizationGrade`；分数采用宿主结果，eval 仍独立分析执行过程，不能改写宿主成绩。

诊断包含具体原因、执行记录索引、可实施的 instructions / skills / tools / procedure 建议、已证实事实与推测，以及证据覆盖范围。长记录按连续片段完整分析后再综合，不把截断记录当作完整执行。完整诊断留在报告与日志中。

Desktop 的 eval 使用独立文件读写流程：会话及实际工具记录保存到只读的 `inputs/conversation.json`，该版本指令和评分依据另存 `inputs/context.json`，实际启用的 Skill 与生成工具资源另存 `inputs/configuration-NNN.md`，context 列出源路径和执行包哈希，初始 user 消息仅包含文件入口、输入哈希及输出协议；eval 用 `file_read` 完整读取，然后用 `file_write` 将 JSON 写入 `assessment.json`。框架核对完整读取覆盖、JSON 格式、字段约束和证据引用，将有效性及原因写入 `validation.json`。较大的文件读取结果按完整行返回结构化预览，包含实际返回的 `end_line` 与下一段起点；框架只累计确实返回的行，不把请求范围当作已读范围。聊天回复不能代替输出文件。不合格时最多重评两次，并将原因及原始证据再次交给 eval；不重跑目标执行。训练、验证的评估文件与人看的 test 分开，调优方只能读分类后的训练分析。

文件模式的一次完整对话使用一份评估输入，不再由框架拆成多个独立诊断；eval 可按行分段读完文件。会话文件是简单的消息数组：`role` / `content`、工具名称 / 参数 / 结果，以及可选的时间戳。每次重复执行独立保存，不嵌套 trials，不混入运行元数据或重复评分。运行状态、重试与审计事件仍保留在框架审计记录中。按评分结束的旧模式仍逐轮评分；`dialogue_completion=user` 则在整段执行结束后只评分一次，再诊断一次，使用该执行版本的实际指令。未评分的中间轮次为 `grade=null`，不会伪造0分。未配置文件工具的 SDK 调用保持原有内联协议。

页面“打开优化文件夹”打开当前实验根目录，其中 `README.md` 提供导航。私有评估文件位于 `evaluations/round-NNN/<case-key>/trial-NNN/<input-hash>/`；分类训练材料及候选包位于下述 `workspace/iterations/`，test 位于 `human-test/`，不交给调优方。

同一训练题重复执行出现不同结果时，eval 对照各次完整记录，找出成功步骤、最早失败分岔与可复用的干预方式。它核对实际政策和工具结果，不把一次成功的所有动作都当作必要条件。每轮调优前，eval 再将训练诊断汇总为有案例依据的优化优先级；调优 Agent 优先使用该清单，而不是自行逐题重新归因。

启用日志时，在日志所在目录生成 `iterations/round-000/`（基线）、`round-001/`（第一轮）、`round-002/` 等独立目录。每轮 `input/training-evidence/` 保存调优时实际使用的父版本证据，`evaluation/training-evidence/` 保存本轮候选的真实执行结果；`proposal.json` 和 `decision.json` 保存变更与采纳结论。未执行的候选不生成执行结果，复用评估会在结论中标明。验证集单独保存匿名数字到 `validation-scores.json`，仅供宿主和人工审计，不复制到调优方的 `editor/evidence/`；测试材料不进入这些目录。原始日志仍是审计依据，旧目录不会因升级被删除。

训练证据有入口索引、`mixed/` 波动题、`failed/` 全部失败题、`passed/` 全部通过题。每组有索引，每题的 `index.json` 链接一份 `case.json`、逐次 `execution-NNN.json` 对话及工具记录、`assessment-NNN.json` 评分与 eval 诊断，已有的成败对照单独保存为 `comparison.json`。`case.json` 保留训练题的 input、rubric、mode 和可选的 user_context，补全多轮对话只以问候开场时的完整场景；不包含参考答案或环境权限。场景中的未披露事实与后续意图不代表执行方已知信息或用户授权，不应复制成生产提示词里的具体答案。问题只保存一次，不在每次执行中重复。优先阅读波动与失败数据，成功数据用于保留有效行为。验证题和测试题不进入训练文件夹，参考答案字段也不直接转交调优方。文件编辑模式下，调优 Agent 从 `evidence/training-evidence/index.json` 进入，索引内路径相对于 `evidence/`。

评估将原始职责与候选的执行指令分开处理：指令改动后，单次诊断、重复执行对照、默认模型评分和训练诊断汇总都会获得独立的 original_policy。原始职责决定权限边界，候选新增的限制不能自动成为不可修改的业务规则。合规但未完成目标的执行，可以提出有适用条件和反证的改进假设；假设必须明确标记，不能强行找错、补造授权或修改固定评分。

题库预审判断多轮对话是否存在合法的信息获取、澄清、确认与执行路径，不要求起始问题已经包含后续确认或可通过授权工具取得的事实。政策作用范围结合完整段落、具体操作章节、参数和状态转换解释；有文本支持且保留全部明确义务的自洽解释，可以将措辞歧义列为提示。不可协调的目标／政策冲突、缺失且无法取得的必要事实，以及明确的通用限制仍应阻断。模型高分、参考动作或工具接受请求，都不能成为绕过明确禁止条件的依据。

原有训练入口新增 `experience` 路径，指向同目录的 `experience.md`。调优方先读累计经验，再查当前训练证据；通过 `experience_notes` 返回本轮新增的可复用经验、适用条件、证据和待验证假设。宿主结合实际采纳状态与训练结果构建文档，不复制验证/test 题目、参考答案字段或私有拒绝理由。经验不进入生产 package；未采纳或未评测的尝试也会明确标记，不能当作已有能力。每轮 `input/training-evidence/experience.md` 保存调优前的快照，`editor/evidence/` 中为只读副本，轮次根目录 `experience.md` 保存本轮结束后的累计快照。恢复从日志中的实际轮次记录重建经验，不信任可变工作文件；不会只保留最近四轮。

Desktop 新实验将独立的 `runtime/rsi/<run-id>/workspace/` 注册为项目工作区，运行记录返回 `workspace_id` 与 `workspace_path`，可通过现有工作区文件接口浏览。每轮目录为：

```text
workspace/iterations/round-001/
  input/training-evidence/          # 调优时的父版本执行评估
  editor/
    package/
      manifest.json                # Agent 配置
      dependencies.json
      files/prompts/rsi-system.md  # 初始为 inline 时生成；已有路径保持
      files/skills/<name>/SKILL.md
      files/tools/rsi/<name>.json
    evidence/training-evidence/    # 编辑器可读，不可写
  version/package/                 # 校验后封存的完整候选包
  version/package-hash.txt
  evaluation/training-evidence/   # 该封存版本的实际执行评估
  proposal.json                    # 框架从文件导出的差异，非第二个编辑入口
  decision.json
  experience.md                    # 本轮结束后的累计调优经验
```

调优 Agent 的文件工具仅绑定本轮 `editor/`，不开放进程执行，不能修改其他轮次、封存版本、原始日志或隐藏评测材料。所有修改以 package 文件为准，最终回复修改理由和独立的经验笔记；框架检查配置和资源变化，固定规则校验通过后封存，再把同一份 bundle 加载到隔离目录推理。下一轮复制当前采纳版本，未采纳版本保留但不成为下一轮父版本。列表中的原始 Agent 仍需显式应用才改变。

τ-bench 新宿主采用相同目录和文件协议。MCP 源码等普通资源可按宿主授权路径进入 package；保存文件不等于已接通运行时。当前 Desktop/τ 宿主支持新增 Skill 和受限纯工具，尚未提供任意 MCP 服务源码的构建、stdio 启动与版本绑定。它们仍须通过单独的宿主执行接入，不能伪称代码已经参与推理。旧实验不能直接改用新编辑协议恢复；保留证据，另建实验，经过核对的相同基线执行可复用。

对话卡片分别跟随自己的最新消息，手动向上阅读后暂停跟随，回到底部再恢复；系统减少动画设置同样生效。宿主可用 `input_visibility=opaque_fixture` 声明输入是内部任务路由，气泡等待真实对话证据后再显示内容。前端轮询使用 `compact=true`，省略重复的底层事件、工具结果副本及内部 Agent 请求正文，保留实际对话、评分、诊断和版本差异。默认 API 仍可读取完整记录，原始日志与执行评估文件不受影响。

最近被拒候选的重要训练执行另放在 `attempts/round-N/`：保留失败、波动、当前父版本尚未测过的新训练题，以及相对于保留版本在本次比较指标上改善的局部成功路径。入口提供同题分析链接、训练退步列表及 training_improvements 的指标与前后分数。整体被拒不代表其中每个步骤都无用；局部改善也不证明整体收益或因果关系。已在父版本通过的未变化轨迹不重复复制。拒绝理由中的 dev 细节不会进入该文件夹，不能将被拒提案当作当前版本。

宿主显式给调优 Agent 配置只读 `file_read` 并绑定工作目录时，上下文只放入口索引与优先级，按需读详细记录。Desktop 与 τ-bench 宿主通过 SDK 的 `tuner_workspace` 将训练证据直接写入同一持久目录，完整记录不装入 Agent 包，因此不占用包的 256 文件 / 4 MiB 配额；宿主负责把文件工具绑定到这个目录。没有指定持久目录的 SDK 调用仍支持将小型证据随调优包提供；没有文件读取授权时继续使用有预算的内联训练反馈，不隐式增加工具权限。诊断输出格式或长度不合规时最多请求两次格式修正，保留原始响应，不重跑被测 Agent，也不借修正更改数值评分。诊断与优先级也会接收可编辑范围，区分 Agent 可修复的行为与不可修改的环境缺陷。

验证题的成绩与诊断保留给宿主和人查看，不进入调优 Agent 输入；人看的 test 由独立观察宿主控制，绝不进入训练诊断汇总。

## Python API 与可优化范围

参见[完整 API 与示例](https://github.com/ZHangZHengEric/Sage/blob/main/sagents/v2/optimization/README.md)。`AgentPackageTestGenerator` 也可独立生成可审查的问题集合；用户可以直接提供 `OptimizationSuite` 与 `OptimizationFinalSuite`。

`optimize(..., rounds=10, optimization_scope=("skills",), constraints=...)` 限制本次允许修改的部分。支持 `instructions`、`skills`、`tools`、`budgets`、`resources`，可以组合。范围选择不会授予文件或能力权限：constraints 仍需分别允许可编辑文件、新建路径、Tool/Skill 候选和预算字段。新增外部 Tool/Skill 名称需要宿主提供可用且授权的绑定；宿主也可显式授予下述包内 Skill 与纯工具创建权限。工具源码实现、模型路由、凭据、策略和执行流程仍受保护。

Desktop 默认只做固定规则校验，不构造候选或数据集审查 Agent。SDK 宿主若显式提供 `suite_reviewer=OptimizationAgent(...)`，仍可选择额外的模型语义诊断；不再自动复用评测 Agent。硬性校验与语义预审分开：协议、必填字段、重复 ID、split、环境绑定及评分器自测错误在执行前阻断，并报告字段或 case ID。模型对缺少信息、不可解或政策冲突的判断只是诊断，需要说明证据、影响与不确定性。导入的固定题集在保存否决意见后仍按原题和原评分器执行，不会改写 `approved=false`。显式启用语义预审时，生成草稿先交回出题角色限次修复（`SuitePreflightPolicy.generated_repairs` 默认 2），失败题进入隔离记录，不进入正式训练；若已无合法的必要初始集合，保留 `OptimizationSuiteReviewRejected` 及其 `review`、`call`，不会以删除异常来伪造有效实验。传输失败、无效模型响应及运行错误仍按各自的异常处理。

桌面导入 `sage.rsi.dataset/v1` 时创建不可变数据集版本。语义诊断中可选择“人工审核并决定是否创建排除版本”：先查看原始题目、评分要求、证据和影响，再填写数据缺陷类型、原因和证据并明确勾选确认。低分、失败、波动和模型暂时不会解不构成排除理由。原始题目不物理删除；排除标记记录 case ID、原因、证据、认证操作者、时间和来源数据集版本。模型调优 API 不提供排除能力，也不能通过 proposal 修改题目、分母或评分标准。

确认只会创建新的“修订集”版本，并将其填入待启动配置，不会启动、取消或修改当前实验。页面同时展示原始题数、排除题数和参与题数，以及当前实验与待启动版本各自的口径。完整原始 test 的目标仍以原始题数为分母；修订集成绩不能标作完整官方集成绩。当前实验中发现的疑点只作为诊断记录保存，应用修订必须开启新实验，旧结果和冻结分母保留。

每次启动冻结数据集版本、参与 ID、排除记录和预审策略；它们与模型、环境和评分器绑定共同参与恢复校验。恢复不采用后来创建的数据集版本，也不接受快照、排除清单或预审策略漂移。预审策略变化属于引擎变化，旧实验需使用原引擎恢复。dev/test 的题目、过程和诊断不进入调优证据；模型侧 MCP 的详细读取也隐藏这些数据。数据集版本元数据只向优化器传递统计及完整人工口径的摘要绑定，原始 test 及排除证据保留在人工接口中。

人工界面使用 `POST /api/v2/agents/{agent_id}/rsi/datasets` 校验和导入，`GET .../datasets/{version_id}` 查看原始数据与排除标记，`POST .../datasets/{version_id}/revisions` 在 `confirmed=true`、明确来源版本和具体证据下创建新版本。启动请求通过 `dataset_version_id` 选择该不可变版本；这三项数据管理能力不注册为调优或 RSI MCP 工具。

导入时立即执行确定性校验并保存 `validation` 报告，导入成功后自动打开数据集详情弹窗，显示总题数、train/dev/test 数量、单轮/多轮数量、多轮上限、参考答案数量、覆盖标签和环境工具检查结果。页面保留“查看详情”入口，可再次查看当前准备版本或旧实验冻结版本；弹窗支持按 ID/内容搜索题目、按 split 筛选，以及查看原题、评分规则、上下文、参考答案和排除记录。错误定位到字段或题目，未通过的导入不创建版本。报告区分已通过、无需检查和尚未检查；评分器仍须单独自测，启动时重新验证环境绑定。多轮上下文为空等疑点仅作为人工检查提示。示例题和诊断仅供用户查看，不进入调优角色输入。

`result.iterations` 包含原版与每个有效候选的完整 package、修改、审查和已有测试记录。无效提案留在报告中，但不产生可执行 package。可选的 `journal_path` 持续保存进度和失败前的证据；中止时没有正常结果，也不会自动重放调用。提供给模型的反馈限制诊断片段和历史提案数量，调用方可见的完整记录仍保留。宿主还应配置 token、资源预算和超时；片段截断不等于完整提示词预算。

## 可创建的能力与重复评测

宿主可设置 `OptimizationConstraints(allow_skill_changes=True, allow_skill_creation=True, allow_tool_changes=True, allow_tool_creation=True)`，并在 `optimization_scope` 中选择 `skills` / `tools`。调优提案的 `skill_definitions` 将名称映射到完整 `SKILL.md`，内容与候选包一起版本化；`skills` 是启用名称列表。这样无需预先把新 Skill 名称逐个写死。创建权限只作用于包内 Skill；不会授予新凭据、网络或进程权限。

`tool_definitions` 可创建有界的纯 JSON 表达式工具。除算术、比较和条件分支外，支持 `filter/map/sort`（`item` 表示当前元素）、`length/sum/at`。每个集合最多 256 项，每次执行最多 20000 个表达式步骤。它们可以处理检索结果、排序与检查，不执行任意代码或外部副作用。原有业务工具仍由宿主绑定。

预填充 `OptimizationCase` 可带 `reference_answer`。评测方接收它和固定 rubric；目标只接收 input，模拟用户只接收用户上下文。训练参考可作为训练反馈，dev 参考和反馈仍对调优方隐藏，test 保留在人看的独立观察器中。参考答案本身应由宿主核对，不能把未经验证的模型答案自动视作真值。

`evaluation_repeats=3, evaluation_aggregation="mean"` 使用三次平均评分选版，保留全部逐次执行与评测记录；`passed` 仍要求每次均通过，用于可靠性和稳定达标检查。默认 `minimum` 保留旧客户端的保守聚合行为。`refresh_incumbent=True` 在候选通过固定规则校验后，同时重新评测保留版本，再与候选比较，避免长期沿用历史偶然成绩。支持种子的宿主可从 `OPTIMIZATION_TRIAL` 取得同一组试验编号。

对于已有完整固定训练集的场景，可传 `suite` 并设 `grow_training=False`，首轮就覆盖所有训练题；仍保留独立 dev 和仅按 dev 分数采纳的规则。允许增长时，默认按退化门槛补充训练挑战。这些选项在通用 SDK 中实现，没有嵌入具体基准的业务规则。

扩增与采纳是两项独立判断。退化沿用共同训练题和宿主私有 dev 逐题的降分／由通过转为未通过记录；验证分数进步仍可采纳，但未修复的退化会暂停扩增。被拒绝候选的退化也会使下一轮暂停扩增，已有题目继续完整重测。没有完整测量的轮次不能被当作“没有退化”。训练题全部通过是例外，但必须覆盖当前完整训练集，不能只看旧子集。稳定性复测的新失败同样参与判断，不使用独立 test 的结果。暂停原因写入 `training_growth_deferred`，调优请求中的 `training_growth` 只提供是否扩增及训练统计，不提供 dev 退化计数或暂停原因；暂停并不证明训练退化，调优方应依据已有训练证据判断下一步；恢复执行会重建相同扩增决定。

可信本地宿主可使用 `examples/v2/desktop_optimization_mirror.py` 把外部 RSI 日志镜像到现有桌面运行历史。曲线、点阵、过程和包 diff 使用同一套生产组件；外部版本保持只读，因为它可能依赖桌面未安装的业务工具。镜像是单向观察，不给调优方提供 test 分数。

## Desktop 历史与应用确认

Agent 配置提供独立的 **RSI** 和 **版本历史** 入口。RSI 页面显示后台运行历史及每轮候选；Agent 层级的版本历史显示人工保存和确认应用的配置版本。尚未应用的 RSI 候选保留在对应运行记录中。

离开页面不会停止 sidecar 中的后台任务。重新进入可以查看持久化进度、测试回答和审查问题。sidecar 退出后，未完成任务标为 interrupted。新建的本地 RSI 实验可点击“恢复进化”，继续同一条记录；已完成 case、eval 诊断、出题响应、调优与审查决策按原值复用，原始日志保留。

调优不改变当前配置。用户需预览版本，点击“使用此版本”，再明确确认。后端检查当前配置指纹，拒绝覆盖已变化的配置，也拒绝未完成的候选；旧实验若记录了语义审查拒绝，仍保留该限制。用户选择其他已完成迭代时，可以看到该版本是否接受了最终测试。

Desktop 当前支持 simple Agent、原生工具、临时工作区和宿主沙箱限制。MCP 仅支持数据集通过 `sage.rsi.case/v1` 显式绑定的 stdio 隔离环境；任意外部 MCP、Shell 测试绑定与非 simple Agent 尚不支持。任务由单个 sidecar 持久化，支持用户恢复和明确临时模型故障后的自动恢复，不提供分布式接管。恢复会校验模型、Agent 配置、题目/评测参数和优化引擎指纹；更改这些条件会拒绝继续同一实验。桌面测试宿主仅允许隔离工作区写操作及无副作用/读操作，因而可以丢弃未完成的工作区并续跑；通用 SDK 对未知外部执行默认要求宿主核实。参见[Desktop 实现指南](https://github.com/ZHangZHengEric/Sage/blob/main/app/v2/desktop/README.md#rsi-与-agent-版本)。

## 真实模型实验

显式启用的[垂类实验脚本](https://github.com/ZHangZHengEric/Sage/blob/main/examples/v2/optimizer_domains.py) 通过 `--catalog` 显式读取 JSON 模型目录中的 `openai-responses` 提供者，产生真实模型费用。它导出原始 package、每轮 package、测试集、模型调用与 Session 证据、评测、审查和对比摘要。凭据只在内存中解析，输出目录必须是新目录，不会激活生产 Agent。

2026-10-12 的只优化 Skill 与工具选择实验分别达到最终测试 3/3。联合范围也达到 3/3，但只修改了 Skill，尚未验证指令与 Skill 同时修改。三组均执行四轮提案，第一轮接受后，后续轮次没有新修改。Skill/工具组复用了以前实验的最终题目，只能作为回归验证；明确精度约定后的联合组使用新封存题目。评估结果时应保留失败记录和审查拒绝，不能将这些小样本结果作为 RSI 普遍可靠性的证明。

### 候选提示词、Skill 与工具的职责

Skill 名称应对应实际实现的可复用能力，使用简洁的“小写单词-连字符”形式，并体现动作及对象或领域；不要按优化过程命名为 `rsi-guidance` 等通用容器。新 Skill 的 YAML 头包含 `name`、`description`，描述说明做什么及何时加载，正文定义前置条件、输入、步骤、结果校验和失败处理。目录名、`name`、manifest 绑定和 `load_skill` 引用须一致；重命名时一起更新并移除旧资源。Desktop 不再预置通用候选名，调优角色在已授权范围内选择能力名称。名称是否符合实际流程作为调优 Agent 的编写要求，不额外调用模型裁决；框架检查已声明元数据的名称、描述和绑定一致性，仍兼容没有 YAML 头的旧 Skill。历史已冻结版本保持原样。

调优 Agent 收到统一编写原则：system prompt 承载常驻规则、优先级、Skill 加载条件及完成检查；Skill 承载按需使用的多步流程，明确触发条件、输入、分支、工具调用、结果校验与失败处理；工具实现可验证的计算或受控动作。Skill 编写参考 Voyager 的可复用与可组合能力：名称及描述说明何时使用，列出前置条件和可观察的完成状态，对实体、标识和值进行参数化，复用实际可用的工具或 Skill，避免臆造依赖、循环调用和复制整段探索轨迹。检查实际工具返回结果，处理缺少输入、空结果、错误和状态变化，明确澄清、停止与恢复条件，不能盲目重试结果未知的外部动作。失败和波动执行用于定位错误决策及其原因，成功执行用于检查修正是否保留已有能力。不得把具体 case 答案、优化过程说明或补丁历史写进生产提示词，也不能把某次成功轨迹固化为无条件流程。

文件编辑模式由框架从实际文件推导 `system_prompt` 等内部差异，不要求调优 Agent 返回这些字段。旧 SDK 的 `system_prompt` 是完整替换文本，未提供则保留当前候选提示词；与旧版 `instruction_guidance` 互斥，受独立权限、长度及优化范围约束。Desktop 和 τ-bench 新实验关闭旧版追加模式；已有实验记录保留原样。改写只产生实验候选，仍需用户显式应用才改变列表中的 Agent。


## 自定义评分器与执行诊断

内置评分默认仍为**质量**，保持原有选版规则。可显式选择**质量与成本**、**质量与耗时**、**质量与 Token 用量**；Desktop 从评分器选择入口使用，MCP 的 `rsi_start` 使用 `builtin_scoring="quality_cost"` 等名称，SDK/API 使用 `BuiltinScoring` 配置。资源数据来自目标 Agent 的实际执行，不由模型估算，且不包含调优、出题和评估开销。

每个样例的每次独立执行分别保存完整 Session 的输入、输出、缓存输入、推理 token、费用及 `usage_reported`。原生 runner 从持久事件读取每次执行边界的新增用量，不受训练轨迹截断限制；等待用户输入后继续同一个 Run 时只记新增部分，再将全部对话轮次相加，避免重复累计。缓存输入已经包含在总输入中，不再额外相加；重复试验保留逐次原值。缺失或不完整的提供方用量不视作零消耗，Token 模式要求 `usage_reported=True`；自定义 runner 也需显式提供这个完整性标记。所有原值保留在原有审计与评估记录中，不另建训练目录。

效率模式保留原始质量成绩、诊断与通过状态，另算选版分 `质量 × (1 - 权重 + 权重 / (1 + 用量 / 参考量))`；默认效率权重 0.2，参考量分别为 1 个宿主报告的费用单位、60 秒、10000 个输入与输出 token，可由 SDK/API 配置并随恢复指纹冻结。质量为零不能靠便宜获得分数。这些显式选择的模式允许质量与效率折中，达标和稳定成功仍按质量与通过状态检查；同题选版及重复试验沿用原有权重和聚合方式。报告分别保存 `grade.score`、`objective_score`、`score_metrics` 和轮次的选版分变化；人看的 test 仍测质量。选择费用模式但没有实际费用数据时明确失败，不把未知费用算作零。外部评分器也可以提供质量成绩，再由宿主按所选内置模式计算选版分。

未选择评分器时，由内部 eval 评分并分析执行。选择自定义 Python 评分器后，所有规则判定、模型评判及数字分数由 `score(request)` 内部完成，框架仅传入标准数据与执行证据并验证返回协议，提供可直接使用的 ModelProvider 代理供评分器自主调用，底层复用 Sage 的模型适配与并发预算，但不提供模型代评通道。eval 继续分析完整执行的原因、优点、不稳定路径及改进建议，不能改变评分器的分数或通过状态。评分器的异常、超时或明确不适用均不能回退到内部评分。数字分数用于选版与收敛；test 仍仅供人观察。格式与示例见 [数据集及评分器协议](https://github.com/ZHangZHengEric/Sage/blob/main/evaluation_datasets/README.md)。

同名 Python 文件按源码哈希区分版本，不覆盖历史实验绑定的评分器。内容相同的重复导入复用原版本；内容变化则新建版本并自动选中。选择列表用短哈希区分同名条目，显示首次导入时间、自测状态及同名最新版本标记；旧记录未保存时间时明确显示“导入时间未记录”。重复导入旧内容不改变首次时间，也不把它重新排序成最新版本。


### 场景对话的完成条件

标准案例可设置 `dialogue_completion=user`。此模式下，由模拟用户推进到场景完成、无法继续或轮次上限，然后才调用评分器一次、诊断一次。中间轮次只保存执行，不提前评分。默认 `score` 保留原有按评分通过结束的行为。对话题的身份由初始输入与用户场景共同确定；不同场景使用同一句问候不会被判成重复题。训练和仅供人查看的 test 使用同一套用户模拟边界，目标只能看到用户实际发出的消息。


页面根据真实阶段区分“计算评分”“准备诊断结果”“修正评估记录”和“等待恢复”，并按未完成调用显示并行数量。评分失败或取消会关闭该调用；恢复等待不会继续显示旧的执行任务。

Desktop 的隔离训练调用发生超时或执行异常后，从审计断点自动恢复，不因第一次调用失败而结束实验。执行、出题、评分、诊断、调优及审查沿用各自已有的隔离与恢复授权；已完成的执行和已保存的评分复用，未完成的私有编辑／评估工作重新准备。普通调用最多追加 3 次恢复，已明确分类的瞬时模型传输错误最多追加 12 次；额度按轮次、角色、题目和重复执行分别计算，退避等待依次为 2、4、8 秒，最高 60 秒。权限拒绝、冻结资源或配置不匹配、未知外部副作用以及用户取消不通过这一机制绕过；重试耗尽仍保存断点和不含私密正文的错误元数据，不伪造分数。


默认内部评分同样必须对完整执行给出诊断。文件模式下仅写分数不合格；内嵌诊断的证据索引按照实际提供的简单会话数组校验，不允许引用不存在的运行事件。外部评分器仍是唯一数值权威。

独立 test 的执行、评分与诊断分别保留不含题目内容的错误阶段/代码。只重试明确的瞬时传输错误，不重采样有效0分；评分或诊断重试复用现有执行及已有分数。内部无工具角色可安全重试；文件角色须由宿主声明私有目录隔离，重开未完成目标对话则须宿主显式声明可丢弃的模拟环境。默认SDK不给这些写操作或目标重启授权。错误耗尽后保留 error 状态，不能把缺测样本当成0分或从总体均分中静默排除。


### 独立上传模拟用户

“出题 / 数据集导入”“模拟用户”“评分器”是三个独立模块。出题 Agent 明确生成初始
用户问题 `input`、用户背景与目标 `user_context`、`mode=single_turn/dialogue`、
`max_turns`，以及 `dialogue_completion`、评分规则和环境。单轮也可以有很多内部工具步骤。
用户背景只给模拟用户，评分规则和参考答案只给评估端。

页面“模拟用户”默认使用 RSI 内置实现；可点击“导入模拟用户”单独上传 Python，再从列表选择。
与评分器一样按用户、Agent、源码与依赖绑定版本；历史实验保留自己的选择。
Python 模块与内置自定义指令二选一。tau 的实现位于
[`evaluation_datasets/tau_bench/user_simulator.py`](https://github.com/ZHangZHengEric/Sage/blob/main/evaluation_datasets/tau_bench/user_simulator.py)。

模块导出 `reply(request)` 或 `USER_SIMULATOR` 基类实例，返回标准 `can_continue`、
`message`、`rationale`，停止时必须包含 `stop_reason`；可选 `state` 只在当前对话内传递。
它通过 `user_simulator_runtime.get_model_provider()` 调用当前 RSI 内部模型，复用全局及
本轮共享并发预算，不收到远程密钥。导入必须有继续和停止自测；模型自测使用录制响应，
导入不启动 RSI，不访问真实模型。使用 `dialogue_completion=user` 时，模拟用户结束或
轮次耗尽后才评分，结束本身不表示通过。协议、可上传示例及 ModelProvider 用法见
[完整说明](https://github.com/ZHangZHengEric/Sage/blob/main/sagents/v2/optimization/USER_SIMULATORS.md)。

### 下一步验证与机制实验

默认 eval 先回答“接下来应验证什么”：区分 Agent 可控决策、环境、模拟用户、评分疑点和
基础设施问题，保留反证与需要保护的成功行为。训练汇总以 `next_action` 决定测试一个机制、
补充测量、报告测量问题或不修改。没有支持的机制时保留当前版本，不强制改写成功策略。

有改动的候选必须在执行评测前提交 `experiment`，声明一个主要机制、保留版本哈希、适用
条件、修改位置、原规则缺口、预期观测、支持／证伪／无法判断的条件、训练与保护案例以及
退化风险。宿主检查版本绑定和案例边界，保存实验卡、实际改动、候选内容和真实测量；
采纳不等于因果假设已经成立。无改动候选不要求编造实验卡。

新增训练题先用保留版本执行，以独立 `training_challenge` 阶段保存完整结果，再交给 tuner
决定是否修改。不会把新题留到改完后才测，也不会覆盖已有失败。界面的补测均分使用完整
保留版本结果，不能用新增题的局部分数替代整体成绩。恢复时补测与候选执行分别识别。

长环境任务可通过 start API 的 `call_timeout_seconds` 配置单次执行期限，默认 240 秒，
训练与独立 test 使用同一期限；整体截止时间仍受宿主上限约束。
