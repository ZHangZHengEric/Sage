# LLM 异常分类与有界恢复

Provider 负责识别协议事实，`ModelRecoveryPolicy` 负责确定恢复动作，Agent Loop 和辅助调用负责执行。正常生成结束与用户任务完成是两个独立判断。不会自动切换 Provider 或模型。

## 模块边界

`model/failures.py` 只归一化错误事实；`model/response_validation.py` 校验响应与结构化输出；`model/recovery_policy.py` 决定动作并提供统一指导模板；`model/recovery_scope.py` 管理共享预算与持久化回调；`model/recovery.py` 和 Agent Loop 执行恢复。Provider 直接依赖错误事实层，不依赖恢复策略。旧策略模块的辅助函数导入路径保留兼容。

共享恢复过程中的并发操作必须全部成功才能释放过程预算；成功的兄弟操作不能清除失败操作的状态。新请求与重启续接使用同一指导模板。超出剩余预算的服务端等待值直接停止，包括极大的有限数值，不进入日期运算溢出路径。

每个逻辑调用使用独立的持久化恢复标识，同用途并发调用只共享过程及 Run 总预算。重建请求 ID 后使用语义指纹匹配唯一的待恢复调用；出现多个候选时明确停止，不猜测归属。指纹只保存摘要值，不记录原始输入。内部参数协商创建或缩短截止时间时，已运行的主调用和辅助调用也立即应用该时限。

摘要传输重试与其他调用共用等待、发送预留和重启续接逻辑，退避期间不占用摘要并发槽位。用户模拟器通过运行时 schema 校验处理各协议的截断，不依赖原始结束字符串，也不新增对 Provider 原生 JSON 能力的要求。

## 契约

`ModelResponse.termination` 是可选、自动归一化的结束状态：`complete`、`tool_calls`、`truncated`、`paused`、`refused`、`empty`、`unknown`。原始 `finish_reason` 保留。无 usage 或 output_tokens=0 的空输出同样检查。只有推理不能替代可交付答案。

`RuntimeErrorInfo.metadata.model_failure` 保存 `model-failure/1` 描述，包括错误类别、阶段、Provider、HTTP 状态、原始错误码、终止原因、等待时间、usage 和副作用状态。`retryable` 仍可由旧客户端读取，但新的恢复决策不再仅依赖它。

共享分类覆盖网络、过载、临时限流、硬额度、鉴权、权限、路由、请求参数、上下文、媒体/请求大小、输出截断、工具参数、空输出、流中断、协议/状态错误、拒绝、容量及未知错误。HTTP 200 内的结构化错误使用同一分类。未知错误默认停止，不推测为暂时故障。

## 默认预算

| 控制项 | 默认值 |
| --- | --- |
| 原样额外重试 | 2 |
| 空响应/仅推理引导 | 1 |
| 参数及结构化输出修复 | 2 |
| 单种参数协商 | 1 |
| 上下文修复 | 6 |
| 单恢复过程额外请求总数 | 6 |
| 单恢复过程时限 | 120 秒 |
| Run 额外恢复请求总数 | 24 |

所有预算同时生效。指数退避从 1 秒起，上限 30 秒，带抖动；服务端有效 `Retry-After` 是最低等待时间。等待超过剩余预算就停止。框架创建的 OpenAI SDK client 设置 `max_retries=0`；注入 client 也应关闭其隐式重试，框架不能核算不可观察的内部网络请求。

通过 `RunConfig.model_recovery` 配置有限预算。兼容字段 `transient_retry_limit` 的显式整数仍有效；新 Run 的 `None` 改为有限默认值，不再代表无限。新旧配置显式冲突会被拒绝。

## 恢复行为

- 网络、过载、临时限流：有界原样重试；额度不足、鉴权和权限错误停止。
- 空输出：追加一次 inference-only 运行时指导。该投影不会成为真实用户消息，不增加授权；复用已提交工具结果，不重放工具。
- 参数 JSON 无效/截断：重新生成完整的小批量调用，不执行残缺调用。
- 上下文超限：请求压缩，输入必须缩减；无法缩减就停止。
- 文本截断、格式校验与无进展纠正：续写/纠正调用同样计入恢复预算。
- 拒绝、安全过滤、未知结束原因：不按空响应处理，不反复请求规避。
- 原生服务端工具暂停：当前路由未实现安全续接时明确停止；本次未新增服务端工具能力。
- 媒体、签名、schema 等问题没有可靠修复器时明确停止，不擅自丢弃输入或编造状态。

辅助调用使用 task-local scope，不能跨独立操作共享计数。Judge 无效输出最多纠正两次，失败不能退回“有文本就完成”；工具选择校验 JSON 结构及可用名称，失败不能开放全部工具。内置模拟器和优化外层识别恢复停止标记，不再重启整轮评估。能力探测只允许传输恢复，禁用改变被测参数的协议协商。

Judge、工具选择和记忆查询的超时按单次模型请求计时，进入同一有限重试策略；Run/恢复过程的总时限耗尽仍直接停止。记忆查询在运行时校验 JSON 契约，保留代码围栏兼容，不要求 Provider 新增原生 schema 能力。结构化输出截断必须重新生成完整对象，不能把半截 JSON 交给业务解析器。

恢复过程只有在最外层语义操作成功后才释放局部次数与时限；嵌套摘要、JSON 纠正和未解决的主调用继续共享原预算。完成标记先持久化，重启时不从旧 checkpoint 复活已结束的时限；Run 累计恢复次数始终保留。

## 持久化与用户体验

Agent checkpoint codec 更新为 `agent-loop/4`，兼容读取旧版本；旧重试计数按已消费预算导入。主调用恢复先写 checkpoint，辅助调用先写恢复事件；发送前持久化 dispatch 标记。重启后读取已预留额度，不返还可能已经发送的请求，已发送但未确认的恢复请求不得复用同一份额度。辅助调用通过 `step.recovery_dispatched` / `step.recovery_completed` 记录发送及完成事实，不重复发送重试通知。

`step.retry_scheduled` 中的 `error.metadata.recovery` 提供版本、动作、次数、时限与原因；主循环结束时 `failure_summary` 提供确定性的说明、已记录工具调用引用及关联 ID。错误说明不再依赖 LLM 调用，也不会把存在产物直接标成任务成功。客户端保持已有消息和产物，清除终态加载状态。

事件中的类别、动作、次数和停止原因可用于聚合恢复成功率及成本。原始报文、凭据和完整工具参数不应成为用户文案或指标标签。

## 验证与升级

运行 `tests/sagents/v2/test_model_recovery_policy.py` 及四个 Provider、Agent Loop、辅助调用和协议转换测试。空响应 session 使用合成数据验证成功工具只执行一次、恢复一次后完成或明确停止。

升级时关注：默认无限重试变为有限；SDK 重试关闭；新 codec 由新版本读取，旧二进制不保证能恢复新 checkpoint。真实 API smoke test 与生产发布需要在相应服务环境另行执行，离线协议测试不等于真实服务验收。
