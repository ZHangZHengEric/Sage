# SAgents V2 回答完整性与使用效果复查

日期：2026-09-12。本轮继续检查核心执行链和 Server 的实际接入，重点是回答是否完整、失败是否被正确呈现、模型能否正常初始化，以及长驻服务中的资源与用户边界。

## 确认并修复的问题

| 问题 | 用户可见影响 | 修复 |
| --- | --- | --- |
| 模型因输出上限停止，默认策略仍可能把非空文本当作最终答案 | 答案说到一半就显示完成 | 四种内置完成策略识别 `length`、`max_tokens`、`max_output_tokens`；在预算内继续，并向下一步提供避免重复的续写指引 |
| 最后一个允许的 Step 返回截断文本 | 步数预算可能绕过未完成判断 | 将截断文本纳入未完成的预算判断，触发已有恢复交互，不额外请求模型 |
| AG-UI 流已发出 `RUN_ERROR`，宿主仍记录 completed | 前端错误与回放状态、成功日志相互矛盾 | 按错误终态保存 failed，并使用失败日志；其他异常路径保持失败处理 |
| Anthropic 路由未指定输出上限时传入显式 `None` | 在发请求之前就无法构造客户端 | 统一工厂保留协议默认值，Anthropic 使用其 4,096 token 默认；显式配置仍保留 |
| Catalog Agent 每个 Run 创建的模型客户端缺少明确所有者 | 连续运行后连接池等资源依赖垃圾回收 | 将客户端加入 Run 资源作用域，在运行结束及装配失败时关闭；宿主注入的共享 fallback 不由该作用域接管 |
| 同步 SDK 初始化发生在事件循环 | 并发启动时其他会话暂时卡顿 | 移入线程，同一事件循环最多 4 个初始化任务；取消后等待构造结束并关闭其结果 |
| 清理第一个资源失败会跳过其他资源；装配后续阶段失败未完整清理已创建作用域 | 失败越多，遗留资源越多 | 使用退出栈按逆序清理所有已注册资源，保留清理失败的异常信号 |
| Host 模型选择优先采用长驻 worker 继承的用户 ContextVar，或根据唯一会话猜用户 | 可能选择错误用户的模型配置 | 显式 Run 查询到的会话绑定优先；无法解析时不猜用户；同一会话的重叠绑定使用引用计数 |
| 摘要超时仅覆盖单次流读取 | 能力查询卡住或格式修复累加时，总耗时超出预期 | 一个逻辑摘要的能力查询与两次格式尝试共享超时；失败仍返回已有可重试错误 |
| Server 技能包读取、解包检查在 async 方法里同步执行 | 加载大型技能时阻塞其他请求 | 通过已有有界技能 I/O 执行器处理 |

截断后的续写会增加必要的模型调用，但不额外调用完成判断模型；仍受 Run 的步数、token 和时间预算控制。已经明确请求交互或带有工具调用的响应继续使用对应协议流程。普通 stop 响应的完成行为保持不变。

## 验证

- 对四种内置完成策略、三个输出上限原因进行参数化验证，并检查预算上限。
- 完整 Agent Loop 测试确认部分答案进入下一次上下文、续写指引实际发送；预算只允许一步时进入恢复状态。
- 模型初始化取消、装配失败、资源关闭失败、多用户绑定和 AG-UI 错误终态均有专项测试。
- 三种官方模型协议均实际构造并关闭客户端，使用占位凭据及不可用域名；不发网络请求。此检查发现并复现了 Anthropic 默认值问题。
- 摘要测试覆盖能力发现永久等待，确保超时能够释放该逻辑调用。

主要新增测试位于 `tests/app/server_v2/test_quality_audit.py`；核心回归补充在 `test_agent_loop_matrix.py`、`test_continuation_judge_matrix.py`、`test_persistent_summary_context_matrix.py` 和 `test_builtin_model_protocols_matrix.py`。

最终 V2 / Desktop / Server 联合回归：**2,357 passed、20 skipped、6 warnings，38.93 秒**。跳过项为未配置的真实模型与数据库、专用 Linux 资源环境，以及默认关闭的持续并发测试。Ruff 与 `git diff --check` 通过。

## 结论边界

本轮解决的是会造成半截答案、错误完成状态、初始化失败和资源遗留的确定性缺陷。测试不等同于模型真实任务准确率，也不能证明压缩后的摘要在所有任务中语义无损。线上模型验收仍需固定任务集，分别统计任务完成率、遗漏要求、错误工具选择、工具失败后的恢复、token 成本和尾延迟。

后续优化已将动态 Catalog 模型改为有界宿主连接池：Run 持有并释放租约，空闲客户端可跨 Run 复用，详见[模型池与增量持久化](sagents-v2-model-pool-and-persistence.md)。单机并发、资源预算和存储边界见[单机并发说明](sagents-v2-single-host-concurrency.md)及[效率审查](sagents-v2-efficiency-quality-audit.md)。
