# SAgents V2 模型复用与增量持久化

2026-09-12，继续优化单机多用户并发。本文补充之前的效率、上下文预算和质量审查，不代表生产容量认证。

## 有界模型客户端池

Server Catalog 模型由宿主池持有，Run 使用租约。相同用户、模型记录、协议、地址、模型名和凭据复用同一客户端；不同用户、变更后的凭据使用不同条目。池键使用这些字段的 SHA-256 摘要，不将原始凭据作为键或指标输出。

- `SAGE_SERVER_MAX_MODEL_CLIENTS` 默认 64，必须为正数。它限制客户端实例数；Run 执行并发仍由调度器参数限制，并不等于 HTTP 连接数上限。
- 同一配置的并发初始化合并为一次；等待者取消不取消其他 Run 共享的初始化。
- Run 完成、失败或取消都释放租约。只有无租约的条目可以淘汰，采用按最近借用顺序的 LRU；正在关闭的条目仍计入容量。
- 容量不足且没有可淘汰条目时返回 `server.model_pool_full`，标记为可重试限流；不会无限堆积初始化等待者。
- 空闲客户端保留到容量淘汰或宿主关闭，不使用定时 TTL。更新凭据后的新 Run 不复用旧客户端，旧 Run 可继续完成。
- 宿主关闭等待租约归还后关闭全部客户端；关闭调用者取消不会中断后台清理，后续关闭可重新等待。清理失败会报告异常并停止新客户端接纳。
- 外部注入的 fallback 仍由其原所有者管理。

可依据活跃用户和模型配置数量调整客户端容量，避免调度执行名额很多而客户端池过小导致限流。

## SQL 事件增量序列化

MySQL / PostgreSQL 原本在每次提交时序列化完整事件列表，随后才切出待追加部分。现在由协调器依据已持久化事件数量，仅序列化待追加的事件，再交给原事务写入。

完整快照导出的默认行为不变；若内存历史比已持久化前缀更短，则导出完整当前历史，由 SQL 事务删除旧记录后重建。删除 Run 的事件清理和提交成功后更新计数的顺序保持不变。

这减少事件日志的重复序列化，不消除会话元数据、命令结果、分叉基础事件等处理成本。SQL 写事务仍使用原来的串行 writer 连接，以保留写锁与提交一致性约束。

## 验证

- 联合回归：`tests/sagents/v2 tests/app/desktop_v2 tests/app/server_v2`，启用 `SAGE_V2_SOAK_SECONDS=30`，**2,377 passed、19 skipped、6 warnings，67.82 秒**。
- 模型池测试覆盖并发初始化、用户及凭据隔离、容量、初始化失败、取消、缓慢淘汰和关闭失败；混合测试用 32 并发、8 用户、40 批共 1,280 次模拟 Run，注入取消和异常，检查每批租约归零且只创建 8 个客户端。
- SQL 投影测试覆盖 10,000 条历史只追加 1 条、没有新增、历史截断、删除 Run 和原完整列表调用方式；两种适配器通过模拟数据库连接检查写入内容与计数。
- Python 3.10 使用项目已有的 exceptiongroup 回移依赖；本地执行环境为 Python 3.12，未宣称执行过 3.10 回归。
- 本轮修改文件 Ruff 检查和 `git diff --check` 通过。

可复现微基准：

```bash
python scripts/benchmark_v2_session_projection.py --events 10000 --repeats 10
```

本地一次结果：完整事件序列化中位数 **95.529 ms**、增量投影 **0.0173 ms**；对应序列化事件数 **10,000 / 1**。基准使用合成长事件列表，其他会话元数据较小，只计协调器序列化，不计 SQL、网络、模型调用或实际任务完成率，不能换算为生产 QPS。

真实 MySQL / PostgreSQL 与模型端点的端到端压测仍未完成。19 个跳过用例包含依赖外部服务或特定平台的测试；6 条告警来自既有 Pydantic 弃用接口。当前证据支持这些具体优化与回归行为，不支持“没有任何问题”或任意并发容量的结论。
