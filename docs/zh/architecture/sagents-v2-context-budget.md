# V2 上下文预算与并发准备

模型请求按以下边界组装。所有裁剪和摘要只作用于请求投影；Session 的原始消息、工具结果及事件保持完整。

`system` 与 `developer` 消息均属于固定指令，不进入历史裁剪或摘要区。已有摘要偏大但存在新的可压缩历史时，允许将两者一起缩短；固定指令与当前必须保留的回合本身超限时直接报错。

| 区域 | 默认约束 | 超限处理 |
| --- | --- | --- |
| System 指令 | 16,384 个估算 token | 明确报错，不裁掉核心指令，也不调用摘要模型尝试压缩 System |
| 必须保留的当前回合 | 最新真实 user 消息及其后续消息；工具调用与结果成组 | 工具结果有持久引用时可以使用引用；仍放不下则报错 |
| 较早的近期历史 | 最多最近 4 个单元，历史部分不超过 8,192 token，且不超过扣除 System 后可用预算的 1/3 | 压缩触发时超出保护额度的历史进入可压缩前缀；必要时进一步放宽历史保护 |
| 可压缩历史 | 按连续前缀压缩，复用并验证既有摘要 | 一次选择完整前缀，分批滚动摘要，不循环重新摘要重叠的原始前缀 |
| 请求预留 | 工具 schema、隐藏工具索引、续跑指引、协议开销、输出预算 | 先预留再压缩，发送前再次检查完整请求 |

标准 Builder / Desktop 接入在没有模型窗口或输入预算时，使用 **32,768 token** 的有限默认窗口。配置已知的真实模型窗口更准确。直接使用 `DefaultContextAssembler(budget=None)` 的自定义宿主仍须提供自己的总输入预算；System 上限始终生效。所有 token 数是估算值，不声称等于供应商实际计费 token。

## 配置

Agent 与全局策略均可配置区域预算，两者取较小值：

```yaml
policies:
  budgets:
    input_tokens: 32768
    system_tokens: 16384
    protected_recent_tokens: 8192

agents:
  main:
    # 其余 name、instructions、models 等按正常 manifest 配置
    budgets:
      system_tokens: 12000
      protected_recent_tokens: 4096
```

`protected_recent_tokens: 0` 表示不额外保护当前回合之前的历史。它不会授权删除当前用户请求。直接使用 Context API 时，对应 `ContextBudget.max_system_tokens` 和 `ContextBudget.protected_recent_tokens`。

Persistent-summary 插件保留 `protected_recent_units`、`summary_target_tokens` 和 `max_summary_source_tokens`，并增加 `max_summary_calls`（默认 4）。默认摘要源预算为 24,000 token，包含为滚动摘要保留的空间；工具调用与结果不会被拆到不同批次。单个超大单元无可用持久引用、或批次数超过工作上限时，在摘要模型调用前报错。摘要插件自身的格式修复最多两次尝试，因此默认最多 4 次逻辑摘要、8 次供应商请求；每次仍受插件超时约束。

摘要输出没有缩小源内容或没有落入最终请求预算时，不写入派生摘要状态，并返回明确错误。不会反复扩大源区重试。同一个最新用户请求内的任意长工具轨迹不会自动变成可压缩历史；宿主应为大型工具输出提供持久引用。

## System 内容来源

- `AGENT.md` 最多 16,000 字符，超限报错，避免静默丢失约束。
- `MEMORY.md` 最多 4,096 字符，`USER.md` 最多 2,048 字符；超限用明确标注的节选。
- SOUL / IDENTITY 保持小型节选。Desktop 文件读取本身也有限制，不先读取整个大文件再截断。
- 可用技能索引最多 128 项 / 12,000 字符的条目预算，描述保持简短，并标记省略。
- 活跃技能默认总预算 6,000 token，计入 XML 转义后的实际注入文本。一个技能本身超限时，在物化前拒绝加载；加载多个技能时淘汰较早的活跃项。原始技能文件不被截断。
- 最终 System 合并后仍检查总上限。因此即使每个来源单独合格，组合超限也不会悄悄发送。

## 服务器并发边界

- 内置估算器每个实例最多保留 2,048 条内容摘要与整数计数，不保留完整提示词。嵌套字段修改会改变内容摘要。
- 一次裁剪对内置可加性估算器只计算每条消息一次，通过累计值计算后缀预算。自定义估算器不默认假定可加性，仍保留完整请求估算语义。
- 同一事件循环的所有实例共享辅助任务名额：token 计算与摘要指纹计算最多 2 个后台任务，技能文件 I/O 最多 8 个，内置模型摘要最多 4 个。
- 等待名额的 CPU 请求不提前向线程池提交任务，也不提前复制快照。取消请求后，已运行的线程继续占用名额直至结束；避免取消风暴突破并发上限。
- 锁只保护短小缓存操作。不同会话不因一个锁等待上游网络；摘要存储仍使用原来的版本校验 / CAS 语义。
- 文件系统技能描述按文件变更信息缓存，缓存上限 2,048 项。单技能查询不扫描整个目录。技能加载锁不永久保留每个历史 Run 的 ID。

这些约束解决本次上下文准备路径的 CPU、内存及辅助请求放大问题。生产总并发还必须由 Scheduler 的进程和租户配额、连接池以及存储插件限制；多进程/多主机部署的存储能力要求不因本次优化而改变。

## 复现与验证

```bash
python scripts/benchmark_v2_context.py --messages 800 --sessions 8
pytest tests/sagents/v2/test_context_efficiency.py tests/sagents/v2/test_skill_provider_matrix.py
```

本地一次合成测试结果（800 条纯文本历史、保留 8 条、无模型与存储 I/O）：

| 场景 | 原裁剪算法 | 优化后 |
| --- | ---: | ---: |
| 单会话耗时 | 2,170 ms | 21 ms |
| 单会话逐消息估算次数 | 320,380 | 800 |
| 8 会话总耗时 | 17,072 ms | 148 ms |
| 8 会话最大事件循环延迟 | 17,067 ms | 29 ms |

基线复现改动前的逐次完整 JSON 计数；两条路径使用相同文本和预算。结果只说明上下文裁剪成本，不等于端到端吞吐或生产容量承诺。硬件、历史大小、估算器、工具 schema 和并发数都会影响实际结果。
