01 / Mental model

先记住四个名词

绝大多数调用链，都是这四层关系的展开。

唯一要先抓住的原则

Session 中已提交的状态与事件才是事实；给模型看的 messages、摘要、缓存和 UI 都是可以重建的视图。

P

Package

sage.yaml 声明要用哪个 Agent、模型、工具、Skill、限制和插件。

S

Session

一段持久对话的并发与历史边界，拥有 canonical history。

R

Run

Session 内的一次执行尝试，可以完成、失败、取消，也可以暂停后恢复。

E

Runtime Event

已经发生并被接受的事实流；宿主用它渲染文本、工具、交互与状态。

05 / One core, many drivers

多 Agent 不是另一套内核

Simple、Fibre、Team 和 Flow 最终都回到同一套 Session、Run、Tool 与 Event 语义。

06 / Side-effect safety

工具调用为什么要有“栅栏”

网络断开时，远端操作可能已经成功。V2 先记录 dispatching，再执行，再确认或协调。

01

记录即将执行

先提交 tool.call.dispatching，留下不可忽略的副作用边界。

02

调用 ToolExecutor

携带 operation_id 与 idempotency_key，执行选定的真实实现。

03

结果不确定

标记 tool.call.unknown，不自动把调用再发一遍。

04

协调或暂停

支持 reconcile 就查询真实结果；否则 checkpoint 后请求人工决策。
