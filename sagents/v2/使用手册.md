# SAgents V2 使用手册

本文是 **能力接入总手册**：如何在 `sage.yaml` 或 `SAgentBuilder` 里选择、配置、替换官方能力。概念说明看 [`README.md`](README.md)，依赖边界看 [`ARCHITECTURE.md`](ARCHITECTURE.md)。不要再为单个模块另写 USAGE。

**运行环境：Python 3.12+。** 低于 3.12 时导入 `sagents.v2` 会立即失败。旧版 Sage runtime 仍是 3.10+。

能力是投影或可替换实现，**不能参与 Session 恢复**。未在 `runtime.capabilities` 里声明时，Builder 使用下表默认插件，不会偷偷换实现。

官方插件是「同一能力、多种实现」。实现类声明 `plugin_id`，与 `runtime.capabilities.*.plugin` 以及 ExtensionRegistry 登记值相同。第三方插件也应在实现类上声明 `plugin_id`。

## 1. 三种接入方式

| 方式 | 适用 |
| --- | --- |
| `sage.yaml` 的 `runtime.capabilities` | 选官方插件并写配置 |
| `SAgentBuilder.with_*` | 宿主已持有连接 / 客户端 / 自定义实现 |
| `register(ExtensionRegistration)` 或 `sage.extensions` 入口点 | 发布第三方插件 |

```yaml
# sage.yaml 选择语法
runtime:
  deployment_profile: controlled_host # controlled_host / distributed
  plugin_trust_policy: trusted_declared # trusted_declared / built_in_only
  capabilities:
    <能力名>:
      plugin: <插件 id>
      config: { ... }          # 可选
      scope: process           # 可选：process / tenant / agent / run
```

`deployment_profile: distributed` 会自动要求跨进程 Session 写入与订阅、事务
outbox、分布式 Scheduler claim/原子 fencing、可重启恢复的 JobRuntime、具备持久
操作账本与重启对账能力的 Tool executor，以及持久且跨进程共享的
Artifact/Package store；Package registry 还必须支持签名验证。
当前内置插件只满足 `controlled_host`，因此误配为分布式时会在 Builder 组合阶段
直接拒绝。

`controlled_host` 不等于只能处理一个对话。一个长寿命 `SAgentApplication` 会通过
有界 worker pool 异步并行处理多个 Session/Run；`max_concurrent_runs` 和
`max_concurrent_runs_per_tenant` 分别控制进程总并发与租户并发。Sandbox 隔离是
独立的宿主责任，不是并发对话的前置条件；服务端应复用 Application，而不是每个
请求重新 build。

Extension scope 只定义生命周期和归属，不会隐式串行调用。Process、tenant、agent
scope 的 provider 可能同时接收多个 Run 请求；插件只能为共享状态加短锁，不能在
模型、网络、子进程等上游 I/O 期间持锁。无法安全共享的插件必须使用 Run scope。

`plugin_trust_policy: trusted_declared` 表示宿主信任 manifest 明确声明的 Python
插件；`built_in_only` 会在加载第三方 entry point 之前拒绝它，并在 plan 阶段拒绝
预注册的外部实现。内置信任由宿主官方 Registry 的注册来源确定，插件不能通过
自行设置 `descriptor.built_in` 获得信任。它是代码准入策略，不是进程或配置隔离；
MCP stdio 命令和远程地址仍需由宿主作为特权配置审核。

```python
application = await (
    SAgentBuilder()
    .with_defaults(session_root="runtime")
    .with_session_store(existing_store)   # 可选，覆盖 yaml 选择
    .build("sage.yaml")
)
```

`with_defaults(session_root=...)` 只提供默认文件系统根；真正选哪个插件仍由 yaml 或 `with_*` 决定。

## 4. Session 存储 `session.store`

一个进程只开一个已知 Session；列表/搜索/归档由宿主自己做。所有后端都是**单进程写**（`multi_process_writes: False`），没有全局 Session 索引。

| 插件 | 说明 | 配置 |
| --- | --- | --- |
| `sage.session.filesystem` | 默认。v4 校验和聚合 + 变更日志为权威 | `root` |
| `sage.session.ephemeral` | 内存，进程退出即丢，测试用 | 无 |
| `sage.session.postgres` | 追加 Run 事件；表前缀 `sagent_` | `dsn` 必填；`schema_name` 默认 `sage_v2`；`table_prefix` 默认 `sagent` |
| `sage.session.mysql` | 同上，InnoDB + `GET_LOCK` | `dsn` 必填（`mysql://.../库名`）；`table_prefix` 默认 `sagent` |

```yaml
runtime:
  capabilities:
    session.store:
      plugin: sage.session.postgres
      config:
        dsn: postgresql://user:pass@127.0.0.1:5432/sage
        schema_name: sage_v2
```

也可 `SAgentBuilder.with_session_store(PostgresSessionStore(dsn=...))`。旧 filesystem 布局启动时不会自动改写，迁移用 `sage v2 migrate --runtime-root <path>`。

## 5. 模型 `model.provider`

在 `models` 里声明路由，不要手写 `runtime.capabilities.model.provider`，除非你要覆盖插件。

| `provider` | 插件 | 协议 |
| --- | --- | --- |
| `openai-responses` | `sage.model.openai-responses` | OpenAI Responses |
| `openai-chat-completions` | `sage.model.openai-chat-completions` | Chat Completions（含兼容网关） |
| `anthropic-messages` | `sage.model.anthropic-messages` | Anthropic Messages |

```yaml
credentials:
  model-key:
    source: env
    key: MODEL_API_KEY

models:
  primary:
    provider: openai-responses
    base_url: https://api.openai.com/v1
    credential: model-key
    model: your-model
    request:
      max_output_tokens: 2048
    limits:
      context_window: 128000
    capabilities:
      tool_calling: true
      reasoning: false
  fast:
    provider: openai-chat-completions
    base_url: https://models.example.com/v1
    credential: model-key
    model: fast-model

agents:
  main:
    models:
      primary: primary
      fast: fast
```

密钥由 `credentials.provider` 解析，不进包文件。也可 `with_model_provider(...)` / `with_model_client(...)`。

`provider_state` 是协议命名空间内的不透明续写状态，Loop 不当作用户可见文本。

每个 `model.provider` 插件必须实现 `probe_capabilities(request)`。探测只允许使用
该插件声明的协议，返回版本化 `ModelCapabilityProfile`，其中包含逐项探测状态
（`supported` / `unsupported` / `error` / `skipped`）和插件私有的
`invocation_strategy`。宿主负责按路由指纹保存 Profile；后续构造 `ModelRoute` 时原样
带回，由同一插件版本解释并应用。协议、插件 ID、插件版本或路由指纹不一致时必须
失效并重新探测，不能跨协议回退。

Chat Completions、Responses、Anthropic Messages 的图片、结构化输出、工具和推理
探测分别由各自插件生成。以 Chat Completions 为例，图片仍是
`messages[].content[].image_url`；兼容变体也只能在这个请求形态内协商，不会改发
Responses 的 `input_image`。

## 7. 工具与技能

### 7.1 官方工具 `sage.tool.official`

文件、Shell、网页等是这个插件内部的工具分组，不是可单独选择的插件。

必须注入沙箱运行时，否则这些工具不可用：

```python
from sagents.v2.tool.official import OfficialToolRuntime

builder.with_tool_runtime(OfficialToolRuntime(sandbox, grant_issuer, job_runtime=...))
# 或 with_execution_binding_provider(...)，按 Run 分配沙箱
```

Agent 的 `tools:` 是授权名单。常用官方工具：

| 类别 | 工具 |
| --- | --- |
| 文件 | `file_read` `file_write` `file_update` `apply_patch` |
| 代码搜索 | `grep` `glob` `list_dir` |
| Shell | `execute_shell_command` `await_shell` `kill_shell` |
| 规划 | `todo_write` `todo_read` `goal_submit` `goal_complete` `turn_status` `tool_expand_tools` |
| 记忆 | `search_memory` |
| 网络 | `fetch_webpages` |
| 媒体 | `analyze_image` |
| 质量 | `read_lints` |
| 交互 | `questionnaire_async` |

也可 `with_tool_provider(catalog, executor)` 完全自带目录，或选 `sage.tool.ephemeral` 用内存 catalog/executor（进程退出即丢；`tools` / `handlers` 由宿主注入）。

`sage.tool.mcp` 的每个 server 可配置 `required`、`max_tools`、`max_pages`、`max_schema_bytes`、`max_result_bytes` 和 `timeout_seconds`。工具发现会读取所有分页，并拒绝重复游标或超出页数/工具数上限的目录；可选 server 发现失败时会隔离该 server。工具执行超时、取消或丢失响应仍按未知副作用处理，不能自动重放。

该插件会明确报告 `durable_operation_ledger: false`、
`supports_restart_reconciliation: false` 和 `protocol_exactly_once: false`。
需要这些保证的部署应通过 `runtime.required_guarantees.tool.executor` 在构建期拒绝
当前 MCP bridge，而不能把进程内去重误认为跨重启 exactly-once。

### 7.2 多 Agent `sage.tool.multi-agent`

`mode: fibre` / `team` 时由 Factory 挂上，不必在 yaml 里选。工具：

- Fibre：`sys_spawn_agent`、`sys_delegate_task`
- Team：`sys_team_delegate_task`

子任务会 **fork 子 Session**（历史隔离），观测 trace 仍挂在**根 Session** 同一条线上。工作区策略显式配置，不从 mode 推断。

### 7.3 MCP `sage.tool.mcp`

```yaml
runtime:
  capabilities:
    tool.catalog:
      plugin: sage.tool.mcp
      name: mcp
      config:
        servers:
          - name: filesystem
            command: npx
            args: ["-y", "@modelcontextprotocol/server-filesystem", "/data"]
```

同时提供 `tool.catalog:mcp` 与 `tool.executor:mcp`。

### 7.4 技能 `sage.skill.filesystem` + `sage.tool.skill`

```yaml
runtime:
  capabilities:
    skill.catalog:
      plugin: sage.skill.filesystem
      config:
        roots: ["./skills"]

agents:
  main:
    skills: [testing]
```

技能按需加载，符号链接安全。`sage.tool.skill` 把已激活技能暴露成工具。

### 7.5 工具选择 `tool.selection-policy`

可替换插件。限制每次请求送给模型的完整 schema 数量。默认 `sage.tool-selection.llm`。

| 插件 | 说明 | 配置 |
| --- | --- | --- |
| `sage.tool-selection.direct` | 全部放行，小目录用 | 无 |
| `sage.tool-selection.llm` | 快模型严格选择相关工具，超时或无效输出时报错 | `max_visible_tools` 默认 24 |
| `sage.tool-selection.lexical` | 本地 BM25 | 同上 |
| `sage.tool-selection.recent` | 最近用过的优先 | 同上 |

```yaml
runtime:
  capabilities:
    tool.selection-policy:
      plugin: sage.tool-selection.lexical
      config:
        max_visible_tools: 16
```

也可用 `with_tool_selection(...)`。模型侧可用 `tool_expand_tools` 展开隐藏工具。

## 9. 续写策略 `agent.continuation-policy`

决定「再调模型 / 完成 / 问用户 / 阻塞」。

| 插件 | 说明 | 配置 |
| --- | --- | --- |
| `sage.agent.continuation.deterministic` | 默认。预算、显式状态、循环恢复、Flow 边界、有工具或文本 | `repeat_threshold` 默认 3 |
| `sage.agent.continuation.llm-judge` | 无工具调用时用 LLM Judge | 需注入 `model`；`model_binding` 默认 `fast` |
| `sage.agent.continuation.hybrid` | 确定性 + Judge | `repeat_threshold`；`model` |
| `sage.agent.continuation.explicit-status` | 只认 `turn_status` | `repeat_threshold` |

```yaml
runtime:
  capabilities:
    agent.continuation-policy:
      plugin: sage.agent.continuation.hybrid
      config:
        repeat_threshold: 3
        model_binding: fast
```

`StartRun.invocation_mode` 是命令字段，不是从用户文本解析：

- `normal`：普通执行
- `plan`：必须提交计划待批准
- `goal`：必须显式 `goal_complete`

## 10. 记忆

长期记忆 ≠ Session。只有 Agent 授权了 `search_memory` 才会启用自动召回。

### 10.1 `memory.provider`

| 插件 | 说明 | 配置 |
| --- | --- | --- |
| `sage.memory.noop` | 默认，逻辑不变只是空实现 | 无 |
| `sage.memory.filesystem-bm25` | SQLite FTS5 BM25 | `root` |

```yaml
runtime:
  capabilities:
    memory.provider:
      plugin: sage.memory.filesystem-bm25
      config:
        root: ./runtime/memory

agents:
  main:
    tools: [search_memory]
    memory:
      recall: true
      auto_write: true
      scope: agent
```

### 10.2 召回查询 `memory.recall-query`

可替换插件。

| 插件 | 说明 |
| --- | --- |
| `sage.memory.recall-query.direct` | 默认，直接用当前用户输入 |
| `sage.memory.recall-query.llm` | 快模型生成关键词；需 `model`；`language` 默认 `en` |

### 10.3 Session Memory `session-memory.provider`

从**当前请求里被省略的历史**里检索，不是长期记忆。
同一 Run 的索引按 canonical ledger 新增后缀递增更新，不会在每次召回时重建并重写完整历史。

| 插件 | 说明 | 配置 |
| --- | --- | --- |
| `sage.session-memory.noop` | 默认 | 无 |
| `sage.session-memory.sqlite-bm25` | SQLite BM25 | `root`；未写则用 `{session_root}/session-memory` |

```yaml
runtime:
  capabilities:
    session-memory.provider:
      plugin: sage.session-memory.sqlite-bm25
      config:
        root: ./runtime/session-memory
```

也可用 `with_memory_provider` / `with_session_memory_provider`。

## 12. 观测（三套独立投影）

都不参与 Session 恢复。Desktop **不**装配 trace-sink。

### 12.1 诊断 `observability.diagnostic-sink`

单次模型调用的脱敏请求/响应，含 `ttfb_ms` / `duration_ms`。

| 插件 | 配置 |
| --- | --- |
| `sage.observability.noop` | 默认 |
| `sage.observability.filesystem` | `root` 必填；可选 `legacy_root` 迁移旧目录 |

```yaml
runtime:
  capabilities:
    observability.diagnostic-sink:
      plugin: sage.observability.filesystem
      config:
        root: ./runtime/diagnostics
```

### 12.2 日志 `observability.log-sink`

结构化 JSONL，字段统一 `sage.log/v1`。

| 插件 | 配置 |
| --- | --- |
| `sage.logging.noop` | 默认 |
| `sage.logging.filesystem` | `root`；`filename` 默认 `sage.jsonl`；`max_bytes` 默认 10MiB；`backup_count` 默认 5；`min_level` 默认 `info` |
| `sage.logging.stdout` | 容器采集。`stream`: `stdout`/`stderr`；`min_level`；`format`: `json`（默认 JSONL）/`text`（控制台一行） |

`AgentLoopEngine` 只实现 `RunDriver.execute/resume` 和循环状态推进，不依赖日志或 Trace。Builder 选择观测插件后，用 `ObservedRunDriver` 包住循环；模型请求继续由 `RecordingModelProvider` 观测。Sink 的选择、生命周期和关闭都属于 `SAgentApplication`，不会进入 Session 权威数据。

```yaml
runtime:
  capabilities:
    observability.log-sink:
      plugin: sage.logging.stdout
      config:
        stream: stdout
        min_level: info
```

### 12.3 追踪 `observability.trace-sink`

`sage.trace.otlp` 是 OTLP 导出插件，**不是 Jaeger**。Jaeger 是后端：把 `endpoint` 指到 Jaeger OTLP（gRPC `4317` 或 HTTP `4318`）。不要再做一个 `sage.trace.jaeger`。

`trace_id = MD5(根 Session)`。Fibre/Team fork 的子 Session 仍在同一条线，挂在父 `tool.call` 下。

```text
agent.run
  ├─ model.request
  ├─ tool.call            含 sys_delegate_task
  │    └─ agent.run       子 Session，同一 trace_id
  │         └─ model.request
  └─ model.request
```

属性保留真实 `session_id`、`root_session_id`、`parent_session_id`，脱敏并截断。完整 LLM 正文只进诊断文件。

| 插件 | 配置 |
| --- | --- |
| `sage.trace.noop` | 默认 |
| `sage.trace.otlp` | `pip install sage[otel]`。`endpoint` 默认 `http://127.0.0.1:4317`；`service_name` 默认 `sage`；`protocol`: `grpc`/`http`；`insecure` 默认 `true` |

```yaml
runtime:
  capabilities:
    observability.trace-sink:
      plugin: sage.trace.otlp
      config:
        endpoint: http://sage-jaeger:4317
        service_name: sage
        protocol: grpc
        insecure: true
```

## 15. 宿主注入一览

| 方法 | 覆盖的能力 |
| --- | --- |
| `with_session_store` | `session.store` |
| `with_derived_state_store` | `derived-state.store`；未提供时，自定义 SessionStore 使用独立内存实现 |
| `with_memory_provider` | `memory.provider` |
| `with_session_memory_provider` | `session-memory.provider` |
| `with_model_provider` / `with_model_client` | 模型 |
| `with_tool_provider` | 整套 catalog + executor |
| `with_tool_runtime` | 官方工具沙箱 |
| `with_execution_binding_provider` | 按 Run 分配沙箱/授权 |
| `with_tool_selection` | `tool.selection-policy` |
| `with_log_sink` | `observability.log-sink`；宿主已持有的进程日志 |
| `with_diagnostic_sink` | `observability.diagnostic-sink`；宿主已持有的模型诊断 |
| `register` | 任意 `ExtensionRegistration` |

`application.resolved_plan` 是最终绑定事实（插件、来源、scope、API 版本、依赖、composition hash），不含密钥。结束时 `await application.close()`。

同一进程 Application 要按新的 manifest 换 Agent/Run 端口（例如 Desktop 的 next_run 组件选择）时，调用 `await application.materialize_agent(manifest, model=..., locked_configs=...)`。它复用进程 scope 和 Dispatcher，**不要**再 `build()`。返回的 `scope_handles` 是 Run 级生命周期，由调用方关闭。

共享 Application 服务多个租户时，必须向 `materialize_agent(..., tenant_id=..., agent_id=..., run_id=...)` 传入完整身份。TENANT/AGENT 缓存按对应身份隔离，PROCESS 插件不会接收租户、Agent 或 Run 身份。

## 16. 自定义插件

```python
from sagents.v2.runtime.extensions import (
    CapabilityOffer,
    ExtensionDescriptor,
    ExtensionRegistration,
    ExtensionScope,
)

builder.register(
    ExtensionRegistration(
        descriptor=ExtensionDescriptor(
            plugin_id="acme.session.custom",
            version="1.0.0",
            name="Custom SessionStore",
            provides=(CapabilityOffer(capability="session.store", api_version="2"),),
            supported_scopes=frozenset({ExtensionScope.PROCESS}),
        ),
        factory=lambda context, dependencies: MyStore(context.config),
    )
)
```

生产插件走 Python 入口点组 `sage.extensions`，入口名必须等于 `plugin_id`。命令、事件顺序、合法 Run 转移、CAS/幂等**不是**插件，不能改。

manifest 应锁定允许的插件版本范围，手动 `register()` 的插件同样会校验：

```yaml
plugins:
  - id: acme.session.custom
    version: ">=1,<2"
```
